# Fund-100 — GitHub Free PRIVATE migration, staged with LIVE STOP

**Decision 19 October 2026:** owner uses GitHub Free and wants the personal Fund-100 public repository private, without paying for GitHub Pro. This document freezes the plan **before installing any new repository secrets or changing visibility**.

## Platform facts and practical consequence

GitHub official documentation: https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/manage-environments

- Free **public** personal repositories support existing `fund100-live-broker` environment secrets, environment variables and protected deployment. In **private** personal repositories on GitHub Free, those environmental rules and secrets become **ignored**; previously stored values reappear if changed back public. They must not be treated as still protective.
- GitHub Free PRIVATE repositories support repository-level Actions secrets and repository variables: https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets.
- **Repo-level secrets do not have environment reviewer gates** and can be referenced by other jobs when workflow source is changed by someone with write access. Static audit, branch checks and STOP are valuable but **do not recreate the revoked GitHub-enforced human approval**. There is no claim that all prior LIVE automation continues identically.
- GitHub app access is installed for **all** repositories under the user installation, observed before migration. Private access still requires a post-change connected fetch/PR verification.
