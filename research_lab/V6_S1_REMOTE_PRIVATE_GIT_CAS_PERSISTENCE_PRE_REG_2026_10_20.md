## Architecture choice

A *new*, standalone GitHub PRIVATE repository proposed as `nicobouch97/fund100-state-private` (not an existing unrelated private repo) will store one mutually exclusive account ledger document on `main`, no workflows, GitHub Pages, outside collaborators or public artifacts. Private GitHub repositories are accessible through the installed GitHub app; **current GitHub tools cannot create that new repository**, so its creation remains a user setup step. Do not silently reuse personal unrelated private repositories.

GitHub Contents API update requires the **current file blob SHA** in its write request; concurrent stale writers should conflict (GitHub's 409/422 results are **NO RETRY**, not success). Offline protocol modeled against original Contents response `sha`, `encoding=base64`, `content`, `path`, and `type=file`. A missing `404` state file, mismatched checksum, remote timeout, malformed response, ambiguous writer outcome or changed account binding is ALWAYS an execution STOP. The ledger never silently initializes on first use. A fresh immutable genesis identifier and independently reviewed anchor will have to be bound into a future LIVE release manifest and verified before any action. A remote force push, deleted/recreated private repository or privileged rollback still needs separately enforced branch restrictions and an independent monotonic anchor: this **prototype does NOT solve rollback attacks**.

Only one original legacy SELL can reserve at a time: ACWI then EEM then XLV; XLE remains held. First CAS records `RESERVED_NO_RETRY`; second independently read-back verified CAS records `POST_MAY_HAVE_BEEN_SENT` **BEFORE** any future separately approved brokerage POST. Once the latter exists, a restart or broker HTTP 404 can NEVER trigger a blind duplicate submission. A future approved controller needs exact original-fill/order-ledger reconciliation and settlement proof. SHA-based concurrency is not itself a broker idempotence guarantee and remote state may eventually require branch integrity settings.

Account binding is a SHA-256 commitment; fractional original quantity is stored only as memory-keyed HMAC-SHA256; authenticated state document is keyed HMAC. In addition to the future private repo authentication, a separately scoped fine-grained PAT with **Contents read/write only for the state repo** would be required in the protected `fund100-live-broker` environment. The default `GITHUB_TOKEN` in the PUBLIC repo does not automatically gain write access to another PRIVATE repository. **No PAT or HMAC key should appear in chat or public code.** The user will only need to add such secrets using GitHub UI when the separate repo exists. Credential-less PR regression tests cannot read or write real state.

This PR delivers **only the offline signed document + compare-and-swap planner and simulated concurrent writer tests**. NO GitHub state repo created; NO authenticated private read/write transport, permissions, secret provisioning, actual time-of-order source account verification, V6-HIGH risk release, brokerage submission or LIVE order enabled. Code specifically keeps `REMOTE_TRANSPORT_RELEASED=False`, `LIVE_ORDER_RELEASED=False`; original V5 protected secrets/STOP untouched. No week-long PAPER profit testing.
